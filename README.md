# AAMM — لوحة فرص الأعمال

تطبيق عربي محلي لإدارة فرص بيع الخدمات والمتابعة. يسجّل العملاء والخدمات، وقيمة الفرصة واحتمالها وموعد الخطوة القادمة، ويعرض ملخصًا وقائمة متابعة ويصدر CSV ومواعيد التقويم. هدفه تنظيم العمل التجاري، **وليس ضمان الدخل** أو إرسال الرسائل أو تحصيل الأموال تلقائيًا. البيانات التجريبية اختيارية ويمكن حذفها.

## التشغيل

يتطلب Python 3.9 أو أحدث، دون حزم خارجية:

```bash
python3 app.py
```

افتح `http://127.0.0.1:8000`. للإيقاف اضغط Ctrl+C؛ لإعادة التشغيل نفّذ الأمر نفسه. تحفظ البيانات افتراضيًا في `data/aamm.sqlite3` ولا تُحذف عند الإيقاف. يمكن تغيير الموقع والمنفذ:

```bash
AAMM_DB=/path/to/aamm.sqlite3 PORT=8001 python3 app.py
```

للتجربة في بيئة معاينة بعيدة يمكن استخدام `AAMM_HOST=0.0.0.0 PORT=8000 python3 app.py`. **لا تدخل بيانات حقيقية في معاينة مشتركة أو مكشوفة.** الخادم للتجربة أو الاستخدام المحلي الموثوق، وليس جاهزًا للنشر العام أو للاستخدام متعدد المستخدمين. لا يتضمن إدارة حسابات أو تشفير قاعدة البيانات أو حماية شاملة ضد إساءة الاستخدام. يمكن تفعيل مصادقة HTTP Basic اختيارية بمتغير البيئة `AAMM_PASSWORD`، واسم المستخدم `aamm`، لكن يجب استخدام HTTPS عبر وكيل موثوق؛ Basic وحدها لا تشفر كلمة المرور. لا تضع كلمة المرور في المستودع أو في سجلات عامة. حتى مع كلمة مرور، لا تعتبر التطبيق جاهزًا للإنتاج العام.

## سير عمل مقترح لتحقيق دخل

1. اختر خدمة واحدة قابلة للتسليم، مثل إنشاء صفحة هبوط أو أتمتة متابعة عميل، وحدد شريحة ومشكلة محددة.
2. اختبر الطلب بمحادثات فردية مشروعة ومحترمة، ثم سجّل الفرص وتاريخ وخطوة المتابعة. لا تجمع بيانات شخصية بلا أساس مناسب أو ترسل رسائل عشوائية.
3. قدّم عرضًا يحدد النطاق والسعر والمدة وشروط الدفع، وسجّل تقدم الفرصة. القيمة المرجّحة هي مجموع (قيمة كل فرصة مفتوحة × احتمال نجاحها)؛ هي تقدير يدوي وليست إيرادًا أو توقعًا مضمونًا. استخدم عملة واحدة متسقة؛ التطبيق لا يحول العملات.
4. عند نجاح الاتفاق سلّم الخدمة وقِس الوقت والتكاليف والتحصيل خارج التطبيق. مرحلة «ناجحة» تعني اتفاقًا مسجلًا، لا إثبات استلام المال.

لا يوجد اتصال تلقائي بالحسابات أو البريد أو بوابات الدفع؛ إضافتها تتطلب إعدادًا واختبارًا وموافقة مناسبة، كما تتطلب سياسات خصوصية وصلاحيات واضحة. لا تضع أسرارًا أو كلمات مرور في الملاحظات.

## المتابعة والتقويم

تظهر أعداد المتابعات المتأخرة والمستحقة اليوم والفرص المفتوحة بلا موعد في قسم «تحتاج اهتمامك»، وفق تاريخ جهاز المتصفح المحلي. اضغط على متابعة لتعديلها. زر «تصدير التقويم» ينزّل ملف ICS يحتوي على الفرص المفتوحة ذات التاريخ فقط (بما فيها المتأخرة)، كأحداث طوال اليوم؛ لا يتضمن ملاحظات الفرصة، لكنه يتضمن اسم العميل والشركة والخطوة القادمة. تعامل معه كبيانات حساسة. استورده يدويًا في تطبيق تقويم موثوق إذا رغبت. لا يرسل التطبيق إشعارات ولا ينشئ أحداثًا في حسابك ولا يزامن التعديلات بعد الاستيراد؛ راجع طريقة تطبيق التقويم في التعامل مع إعادة الاستيراد، فقد تنتج تكرارات أو لا تُحذف الأحداث القديمة. معرّفات الأحداث المحلية تعتمد على رقم الفرصة، فلا تخلط تصديرات قواعد بيانات مختلفة في تقويم واحد.

## النسخ الاحتياطي والاستعادة

لنسخة متسقة أثناء تشغيل التطبيق أو توقفه استخدم واجهة SQLite للنسخ الاحتياطي:

```bash
mkdir -p backups
python3 backup.py "backups/aamm-$(date +%Y%m%d-%H%M%S).sqlite3"
# عند استخدام قاعدة غير افتراضية:
python3 backup.py --source /path/to/aamm.sqlite3 /path/to/new-backup.sqlite3
```

يجب أن يكون مجلد الوجهة موجودًا؛ لا تُستبدل نسخة موجودة، ويُتحقق من سلامة النسخة. تحفظ النسخة بصلاحيات ملف مقيدة عند إنشائها، لكنها غير مشفرة. يمكن جدولتها عبر cron أو مجدول النظام مع مسارات مطلقة، ووجهة خاصة وآمنة، ومراقبة رمز الخروج والتنبيه عند الفشل؛ التطبيق لا ينشئ الجدولة أو يحذف النسخ القديمة بنفسه. اختبر الجدولة والاستعادة ولا تضع النسخ داخل Git. يمكن أيضًا إيقاف التطبيق ونسخ ملف قاعدة البيانات يدويًا. للاستعادة أوقف الخادم واستبدل الملف بنسخة موثوقة ثم أعد تشغيله. احفظ النسخ في مكان مشفر وآمن واختبر الاستعادة دوريًا. زر CSV يصدّر الفرص فقط وليس نسخة لاستعادة قاعدة البيانات؛ بعض القيم النصية الخطرة على برامج الجداول تُسبق بعلامة اقتباس عند التصدير. التطبيق لا ينفذ نسخًا احتياطية تلقائية دون إعداد جدولة خارجية.

## الاختبارات والتطوير

```bash
python3 -m unittest discover -s tests -v
```

`app.py` يحتوي API وقاعدة SQLite، و`backup.py` أداة النسخ، و`static/` الواجهة، و`tests/` الاختبارات. قبل النشر الحقيقي: أضف مصادقة وإدارة جلسات وصلاحيات، HTTPS، حماية CSRF ومعدلات الطلب، سجل تدقيق، نسخًا احتياطية آلية، ترحيل مخطط قاعدة البيانات، ومراجعة الخصوصية والقوانين المحلية. أضف التكاملات الخارجية تدريجيًا على أساس احتياج مثبت بدل افتراض أنها تحقق الربح.
